# dsh-run-button

给 DSH 加一个"启动按钮"：点一下，就像在资源管理器里双击一样运行项目里的启动脚本。

```
┌───────────────────────────────────────────────┐
│ 会话标题栏 …                    [▶] [📂 打开资源管理器] │
└───────────────────────────────────────────────┘
```

- 按钮位于会话标题栏，紧挨着"打开资源管理器"按钮的左边（`conversation.session.header.utilities`，order `-11`）。
- 点击等价于 `cmd /c start "" <脚本>`：新开一个控制台窗口，cwd 是脚本所在目录，脚本独立于 DSH 运行。
- 没有日志面板、没有进程管理——这正是"双击"的语义。

## 绑定

项目根目录下 `.dsh/run-button.json`：

```json
{ "file": "启动.bat", "label": "启动" }
```

- `file`：**工作区内相对路径**，不支持 `..` 和绝对路径。
- `label`：可选，仅用于展示。
- 文件不存在或没有该文件时按钮变暗，悬停显示原因。

## 未绑定时的行为

按钮常驻但不可点。移上去提示"未绑定 · 发现 启动.bat"——候选来自工作区顶层、且**名字像启动脚本**的文件（含 `启动` / `start` / `run` / `dev` / `serve` / `launch`，扩展名 `.bat` / `.cmd` / `.ps1` / `.sh`）。名字无关的脚本（`build.cmd`、`clean.ps1`）不算候选，避免把无关脚本推荐成启动项。

## 模型如何知道

不需要工具。会话里有一行动态提示，**只在相关时出现**：

- 本轮用户消息提到启动类词（启动/运行/脚本/bat/start/run/dev…），或
- 按钮未绑定且工作区顶层存在候选脚本。

提示会给出脚本路径，并告诉模型把绑定写进 `.dsh/run-button.json`。其余时间这条提示不存在，不消耗 token。

> 已知边界：关键词是启发式的，没命中时模型不会主动知道这个功能；它仍可以用 bash 直接把脚本跑起来。

## 安装

```bash
plugin_manager install_bundle  <克隆后的绝对路径>
```

或用 DSH 的插件管理器指向本地目录。

## 目录

```
index.js           宿主半边：读绑定、扫候选、启动脚本、HTTP 路由、提示注入
client.js          浏览器半边：标题栏按钮
cordis.patch.yml   加载器补丁
locale/            插件元数据（en / zh）
icon.svg           图标
```

## 开发

宿主半边注册两个同源接口（仅回环 + 同源）：

- `GET  /api/dsh-run-button/state?cwd=<绝对路径>`
- `POST /api/dsh-run-button/run`  body `{"cwd":"<绝对路径>"}`
